| 2.5.0   | 2026-11-02 | Response to the HACS submission review on hacs/default#13010 by @frenck. The Draco decoder is now bundled with the release instead of fetched from https://www.gstatic.com/draco/versioned/decoders/1.5.6/ at runtime. A new Rollup `copyDraco()` plugin copies `draco_decoder.js`, `draco_decoder.wasm`, and `draco_wasm_wrapper.js` out of `node_modules/three/examples/js/libs/draco/gltf/` into `dist/draco/` at build time. `hacs.json` flipped `zip_release` to true so HACS extracts `dist/` into `/hacsfiles/hass-3d-floorplan/`, keeping `hass-3d-floorplan.js` as the entry file with `draco/` next to it. The release workflow builds, zips `dist/` into `hass-3d-floorplan.zip`, and uploads it alongside the standalone `.js` for older HACS clients. A new `_defaultDracoDecoderPath()` resolves `./draco/` from `import.meta.url` (query/hash stripped), which lands at `/hacsfiles/hass-3d-floorplan/draco/` for HACS installs and `/local/<path>/draco/` for manual installs; the gstatic URL remains as a last-ditch fallback only. Editor's Draco path field shows empty by default with a label explaining the bundled decoder is used when left blank. Offline / air-gapped and strict-firewall installs work out of the box. `draco_decoder_path` override still works for anyone who wants to host the decoder files elsewhere. |
| 2.4.3   | 2026-09-16 | Cover bug fix (reported in #1). The state handler updated `_position[i]` when `current_position` changed but left `_states[i]` holding the previous value, then passed that stale state into `_updatecover` → `_translatedoor`. Because `_translatedoor` only applies a translation when `doorstate` is `"on"` or `"open"`, a closed→open transition rendered the blind fully shut even though position had climbed off zero. Fix: refresh `_states[i]` alongside `_position[i]` and pass the fresh state directly into `_updatecover`. Also switched the position guard to `!== undefined` so a legitimate `current_position: 0` no longer falls through to the state-only branch, and extended `_translatedoor` to treat `"opening"` and `"closing"` like open so mid-travel frames animate to the reported percentage instead of snapping shut. |
| 2.4.2   | 2026-08-17 | Build-time dependency & tooling cleanup — no change to card behavior (verified: build, typecheck, lint, and the Playwright render smoke test all pass). Bumped CI to Node 20 (the upgraded toolchain — ESLint 9, Playwright 1.62 — needs Node ≥ 20; the card is browser code, so this touches only the build, not users). Migrated the deprecated Rollup plugins to their scoped `@rollup/*` successors, replaced the unmaintained `rollup-plugin-typescript2` with the official `@rollup/plugin-typescript`, and bumped `@rollup/plugin-commonjs` 21 → 29 — the last of these clearing the remaining deprecated transitive packages (`glob@7`, `inflight`, `sourcemap-codec`) in favour of `fdir`/`picomatch` + `magic-string@0.30`. Upgraded ESLint 7 → 9 (flat config) with `typescript-eslint` 8. Dropped the `custom-card-helpers` runtime dependency for a small vendored types + `fireEvent` module (`src/ha.ts`), which also removes the `@formatjs/intl-utils` code it dragged into the bundle and the `this`-rewrite build warning. Removed dead code and unused devDependencies (`_handleAction`, `@babel/plugin-proposal-*`, `check-dependencies`, `eslint-config-airbnb-base`, `eslint-plugin-import`/`-prettier`, `eslint-config-prettier`, two no-op statements). Committed a `package-lock.json`, switched CI to `npm ci` with lint + typecheck gates, and removed the stale `yarn.lock`. Added a HACS validation workflow (`hacs/action`, category `plugin`) so structural or `hacs.json` regressions fail CI before users hit a broken install. Net vs. 2.4.1: ~280 fewer installed packages and `npm audit` findings down from 28 to 5; `lit/decorators` imports now use the explicit `.js` path. The deprecations that remain (`@material/mwc-*`, and the runner-side `punycode` line) are deferred to the v3.0.0 editor rewrite or originate outside this repo. |
| 2.4.1   | 2026-08-10 | Bug-fix pass from a code audit. **Security:** `entity_template` now binds `$entity` as a sandboxed parameter instead of substituting the live state into executed code, closing a script-injection path; string states also stop throwing (templates are now expressions — rewrite `if/else` blocks as ternaries). **Memory:** reuse the `CanvasTexture` on text/room updates instead of leaking one GPU texture per sensor tick, and add a `teardown()` that disposes scene geometry/materials/renderer on `rerender()` so editing in the visual editor no longer exhausts WebGL contexts. **Correctness:** entities missing at boot no longer shift every later entity's bindings (index-aligned placeholder arrays; per-entity `_position` slot); guard `sun.sun` so `sky: yes` doesn't crash without the Sun integration; enforce the (previously dead) shadow-caster limit; validate `path`/`objfile` in `setConfig` so bad config shows Home Assistant's error card instead of crashing in the loader. |
| 2.4.0   | 2026-08-03 | Robustness and maintainability pass. Per-entity error isolation in the state handler so one misconfigured binding no longer stops all updates; null-safe panel/sidebar detection that degrades instead of crashing when Home Assistant restructures its frontend; replaced `eval` in entity templates with a scoped `new Function` that also fails gracefully. New `debug` option silences ~20 informational console logs by default (warnings/errors still show). Editor now exposes `max_pixel_ratio`, `model_cache`, `draco_decoder_path`, and `debug`. Loading/error messages are localized (en/de/es/ru/nb). Added an ESLint rule to reject assignment-in-condition, plus a committed browser test harness and Playwright smoke test wired into CI. |
| 2.3.1   | 2026-07-31 | Fixed light color_mode checks that used assignment instead of comparison (corrupted the shared state object and forced a re-render on every light update) and array reference comparisons that never matched. Added WebGL context-loss recovery so the canvas redraws instead of staying blank after mobile browsers evict the GL context. |
